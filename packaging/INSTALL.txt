xcp payload - install in 3 minutes
==================================

This folder makes any wired Xbox-style controller (tested with a Manba One V2)
work as PLAYER 1 on a jailbroken PS4 running GoldHEN, in every screen: home,
settings, sign-in and games. It does that by creating a virtual DualShock 4, so
it is a GoldHEN *payload*, not a plugin.

Files here:

    xcp_payload.elf     the payload (this is the one you need)
    payloads.ini        example AutoRun entry for GoldHEN
    INSTALL.txt         this file


What you need
-------------

* A PS4 on firmware 11.00 (also known to work on 10.01 / 11.02) with GoldHEN
  v2.4b18.10 or newer already running.
* A DS4 still connected, so you can navigate while you set this up.
* The Xbox pad's USB receiver (or cable) in a PS4 USB port.
* FileZilla (or any FTP client) to copy one file over. GoldHEN's FTP server is
  on port 2121, user "ps4", password "ps4".


Step 1 - copy the payload
-------------------------

With FileZilla: connect to the console (SFTP/FTP, port 2121, ps4 / ps4), open
/data/payloads/ on the console, and drag xcp_payload.elf into it.

With a command line (replace the IP):

    curl -u ps4:ps4 -T xcp_payload.elf \
        ftp://192.168.1.123:2121/data/payloads/xcp_payload.elf


Step 2 - start it once
----------------------

On the console: GoldHEN -> Utilities -> Payloader LaunchPad -> run xcp_payload.elf.

A few seconds later the console behaves as if a DS4 had just been plugged in:
"Who's using this controller?" appears. Pick your user and press a button on the
Xbox pad to accept it. The pad is now player 1 everywhere.


Step 3 - make it automatic (optional)
-------------------------------------

In the LaunchPad, highlight xcp_payload.elf and press Square to add it to the
AutoRun queue. Or edit /data/GoldHEN/payloads.ini by hand - see payloads.ini
here for the exact line. After that it starts by itself on every boot.


Touchpad click
--------------

The Xbox pad has no touchpad. The virtual DS4's touchpad CLICK is fired by an
L3+R3 chord: program a back button (e.g. M3) on the controller to an "L3+R3"
macro, and one press does it. A held L3+R3 also works.


How to stop it
--------------

There is no stop button inside the payload. To stop it for good, reboot the
console. Turning the pad off removes the virtual pad (the console goes back to
normal) but the payload keeps running, ready if the pad comes back.


If something is wrong
---------------------

The payload writes a log to /data/xcp_payload.log on the console. Grab it over
FTP and read it, or see docs/DEPLOY-PS4-PAYLOAD.md in the project for the full
guide. The most common issues:

* Nothing happens -> the file is not in /data/payloads/ or GoldHEN is too old.
* "vda patch: ... not patching" -> the payload did not recognise this firmware,
  so it refused to touch the system library. Update the project / report it.
* No "Who's using this controller?" prompt -> the receiver may not be a known
  device; check the "usb:" lines in the log.

Nothing here is permanent and nothing is written outside /data/.
